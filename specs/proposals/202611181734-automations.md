# Proposal: AUTOMATIONS

Status: **settled** (2026-11-18); its specs are written with the work, and lead from then on. It will change
[../ui/screens/](../ui/screens/) (a screen of its own), [../ui/controls.md](../ui/controls.md) (HOME + OP6),
[../files/store.md](../files/store.md) (a kind), [../editor.md](../editor.md), the playground and the manual.

**An automation records the FM-1's controls as they are worked and plays them back:** every key, button and knob, at
the times they came. Sixteen of them, kept in one file. A performance of mutes, knob sweeps or keys played into LOOPS
can be done again by the FM-1 itself, on any screen, in any state: an automation restores nothing but the screen it was
recorded on, and where it lands is the player's to arrange.

## 1. The screen

**HOME + OP6** (the black key HOME's screens leave free) opens **AUTOMATIONS**:

```
AUTOMATIONS                              S: the header
 00 LOOPS   01 EMPTY   02 FX      03 ...  a 4 x 4 grid of slots: its number, the screen it was
    0:42                  1:05            recorded on, its length; EMPTY dimmed
 ...
REC RECORD  PLAY PLAY  SEL MENU          the hint line
```

- **The highlight:** SELECT and ALGORITHM a slot a click (row by row); **a white key** picks a slot (white key *n*,
  1-16: slot *n* − 1, as LOOPS' CONTROL mode numbers its loops). The keys play nothing here.
- **REC** records into the highlighted slot (section 2); a slot holding one asks first (`AUTOMATION 03 HOLDS 0:42` /
  `REPLACE IT?`, OCT+ `REPLACE`, OCT- `KEEP`).
- **PLAY** plays the highlighted slot (section 3); an empty one: `AUTOMATION 03 IS EMPTY`, PLAY blinking.
- **SEL** opens the menu: RECORD, PLAY, CLEAR (`CLEAR AUTOMATION 03?`, CLEAR / KEEP), REVERT (while the file has
  changes not saved: `REVERT AUTOMATIONS TO SAVED?`).
- **HOME** leaves it, as any screen; HOME + OP6 again does nothing more.

## 2. Recording

- REC (or the menu's RECORD) closes AUTOMATIONS and goes back to where it was opened from, as FX goes back; **that
  screen is the automation's**. It waits for the first press, key or turn, which is its time 0 (no silence before it).
  The header shows `● AUTO 03` in red while it records (and waits). HOME + OP6 opens AUTOMATIONS as ever and so ends
  the recording: HOME's press (held back until something else shows it is not this) and OP6's are not recorded.
- **Everything the FM-1 takes as its own input is recorded:** each key and button pressed and released, each knob's
  clicks, MIDI's learned controls and notes as the controls they stand for. **Not recorded:** MASTER (its own, always),
  and **HOME + OP6, which ends the recording** (AUTOMATIONS opens: `AUTOMATION 03 RECORDED: 0:42`; nothing pressed
  yet: `NOTHING RECORDED`, the slot as it was). What is held as it ends is let go in the automation at that time.
- It is an edit: SAVE keeps it, REVERT ALL drops it (and REVERT on AUTOMATIONS' menu, while it has changes). The
  edit memory full ends it (`MEMORY FOR EDITS IS FULL`, what was recorded kept). The events gather in a small buffer and
  go into the edit memory about once a second.

## 3. Playing

- PLAY (or the menu's PLAY) closes AUTOMATIONS, **goes to the automation's screen**, and from there gives the FM-1 the
  recorded input at its times, in place of the controls': each press, release and turn as if made by hand (holds by
  their timing, a question answered by its keys, SAVE saving, HOME's combinations going to other screens). The header
  shows `▶ AUTO 03`. Nothing else is set first: it plays in whatever state the FM-1 is in.
- **Any key, button or knob of the player's stops it** (`AUTOMATION STOPPED`); that press does nothing else (its
  release neither). **MASTER** stays the player's throughout.
- At its end what it holds is let go (`AUTOMATION 03 PLAYED`). It plays once.
- Timing: the main loop gives the events due at each pass (about 1 ms apart; up to a frame's drawing, ~30 ms, while the
  screen draws), in their recorded order; events recorded in one pass come in one pass.

## 4. The record

Kind **0x32** (the system's: settings 0x30, the MIDI map 0x31), number 00, version 1: **one file of the kind, its
records its slots' parts**, sub = the slot × 16 + the part (slot 0-15, part 0-15). An empty slot has none. Each part
is a record of at most 4 KB, so a slot holds about 64 KB (the edit memory holds less); recording rewrites only its
slot's last part, a slot is copied or cleared by its parts, and the store keeps them as any whole records.

| Bytes | Field |
|---|---|
| 0 | part 0 only: the screen it was recorded on (0 STATUS, 1 SONGS, 2 EDITOR, 3 INSTRUMENTS, 4 PLAYBACK, 5 VISUAL, 6 FX, 7 LOOPS, 8 DJ, 9 SETTINGS; another number: where it is) |
| then 2 | the events in this part, little-endian |
| then | the events, bit-packed: whole events in each part (the next part starts on a byte with the next event), the last byte padded with 0 |

**The events** are one after another, bits first to last within each byte (as the instruments' packed fields); a
time counts on across a part's end. An event is its time, then its action:

| Time since the event before (the first: since time 0) | Bits |
|---|---|
| `0` + 5 bits: 0-31 ms (several in one pass: 0) | 6 |
| `10` + 8 bits: 32-287 ms | 10 |
| `110` + 12 bits: 288 ms to 4.4 s | 15 |
| `1110` + 16 bits: to 70 s | 20 |
| `1111` + 24 bits: to 4.6 h | 28 |

| Action | Bits |
|---|---|
| `0` + 6 bits: pressed: key 0-26 (F-3 .. G-5), button 27-40 (OCT-, OCT+, FX, SEL, ENV, LFO, EDIT, GLO, HOME, SAVE, ARP, SEQ, PLAY, REC) | 7 |
| `10` + 6 bits: released (the same numbers) | 8 |
| `11` + 3 bits knob (0 SELECT, 1 ALGORITHM, 2-5 K1-K4, 6 PRESETS; 7 kept) + 4 bits its clicks, −8 to +7 (two's complement, never 0) | 9 |

Presses and releases are explicit (never toggles), so a stream cut or copied anywhere leaves no key down: playback
lets go at its end of all it holds. A note is about 4.4 B (pressed 250 ms after the last event, held 180 ms); busy
playing about 1 KB a minute. Numbers 41-63 of a press or release, and knob 7, are kept for later: a reader skips such an
event.

## 5. The EDITOR

- **The file** is a system item: on the FM-1 panel `AUTOMATIONS` (one, as SETTINGS and LOOPS); on the TABLE any number
  (READ brings the FM-1's, `+ NEW` makes an empty one, WRITE sends one), disks and backups take it.
- **Its tab:** the 16 slots, each its screen, length and events; a slot picked, its events as a table, a row each: the
  time from the start (`0:12.345`), the ms since the last, the event (`KEY C-4 DOWN`, `SEL UP`, `K1 +2`): a row's time and
  event edited, a row deleted or inserted; the slot's screen changed.
- **Copying:** slots marked (click, Shift-click), COPY; in another file's tab PASTE at a slot, asking before replacing
  ones that hold automations, as the cartridge tabs copy instruments.
- **No preview** (an automation drives the FM-1's controls, no sound of its own).

## 6. The playground, tests, room

- **The playground** twins all of it (its own input stands in the same place).
- **Tests:** the stream's coding (every time class and action, a bit stream across bytes and parts) byte for byte with
  the EDITOR's; recording (the first press's time 0, a pass's events together, HOME + OP6 left out and ending it,
  MASTER left out, held keys let go at the end, memory full) and playing (the screen first, the times, a pass's events in
  order, a key of the player's stopping it and doing nothing else, MASTER free, the end letting go); SAVE and a power
  cycle; the screen's controls (the white keys, REC's question, the menu); the EDITOR's (the file through READ and
  WRITE, the table's edits, COPY and PASTE between files).
- **Room:** about 2.5-3.5 KB of code (the screen, the recorder and player in ui.c's input, the record's coding with
  the UI's bit helpers), ~100 B of RAM. The debug build had 384 B left with CUT: a size pass first.
