# Proposal: the voices' split between the cores moved every block

Status: **settled** (2026-11-21); its specs are written with the work, and lead from then on. It changes
[../second-core.md](../second-core.md) (the voices on core 2), [../ui/screens/settings.md](../ui/screens/settings.md)
(VOICES, the load guard), [../debug.md](../debug.md) (the figures, AUTOTEST), the firmware's player, the emulator's
and the playground's estimate of the two cores' work. The sound does not change.

At VOICES 16 the pool's places 1-10 were core 1's and 11-16 core 2's; at VOICES 8 and 12 every place was core 1's. New
notes and returning ghosts take core 1's places first, so core 2 rendered voices only past the tenth note. Measured on
the FM-1 in DJ HEAVY (two songs mixed on DJ): at VOICES 16 core 1 worked 63.4 % of a half on average and core 2 34.3 %,
15 halves late in 30 s; at VOICES 12 core 1 75.3 % and core 2 14.7 % (effects only), 79 late. The ghosts' own work was
0.1 % of a half; what they cost is the notes they bring back, all of them core 1's up to the tenth.

## 1. A split each block

- **The split is a place, chosen each block,** before the voice job is handed over: core 2 renders the sounding places
  from it on, core 1 those before it. Everything else stays as it is: the voice job, core 1 waiting for it where its
  places begin, adding core 2's mixes, the decisions drawn from each voice (its peak into DUCK and the meters, its end)
  in the places' order. The mixes are whole-number sums, so the sound is the same sample for sample wherever the split
  stands.
- **At every VOICES while core 2 runs.** VOICES keeps its meaning, the notes heard at once: 16 needs core 2, 12 is the
  most core 1 renders alone, and while core 2 does not run (SECOND CORE off, not started yet, a fallback) the split
  stands past the last place: core 1 renders them all, as before.
- **Core 2 renders 10 voices at most** in a block (its job's room: about 41 B a voice), so core 1 always keeps some at
  16.
- **Where it stands:** each sounding voice weighs its engine's cost a block (the load guard's weights: DX7 78,
  JUNO-106 64, sampler 52, TB-303 76, CHIP 40). Taken from the top place down, voices go to core 2 while its share,
  with a margin for its effects, stays under core 1's. The margin follows what happened: core 1 kept waiting for core
  2 where its places begin, core 2 gets less from the next block; core 2 done early, more. So the split finds the
  effects' real cost without a table of its own.
- **Unchanged:** a note keeps its place while it sounds (a place is no longer tied to a core); the notes taken from
  their engines fade out on core 1, their last block rendered there whatever their place; a voice whose mute fades this
  block is rendered on core 1; a fallback during a voice job leaves that block's voices of core 2 out (one block, 1.45
  ms) and the split stands past the last place from then on.

## 2. The load guard, deterministic as before

The guard decides when ghosts may come back, so it shapes what is heard, and it is never measured: the FM-1, the
emulator and the playground decide alike. The split's margin follows the FM-1's timing, so the guard does not read the
split: it counts the same voices split by the weights alone, with a fixed allowance for core 2's effects, and holds the
returns while the busier core's count, so made, is over its cap. With core 2 taking voices at VOICES 12 the guard holds
less there than before.

## 3. Measuring it

The debug build has a switch back to the fixed split (places 11-16 on core 2 at VOICES 16, none at 8 and 12) for its
AUTOTEST: DJ HEAVY and DJ HEAVY AT VOICES 12 run both ways in one session (the fixed split as the "before"). The
figures say where the split stood (its mean and its lowest), core 2's voices a job (mean, most) and the blocks core 1
waited at the join.

## 4. Choices made

- A split each block rather than a core chosen at a note's start: it rebalances while notes ring on, and leaves which
  note becomes a ghost as it is.
- The top places to core 2, not any set of voices: the decisions drawn from each voice keep the places' order with no
  change to the mixing loop, and a voice's cost comes from its engine, so a run of places balances to about one voice.
- At VOICES 8 and 12 too: that is where core 1 ran latest with core 2 nearly idle.
- The guard on the weights' split, not the measured one: what is heard stays the same on the FM-1, the emulator and
  the playground.
- Later, not now: moving the Juno-106's chorus and DJ's decks' mix to core 2 (a third hand-over each block, and core
  2's RAM room has 1.3 KB left).
