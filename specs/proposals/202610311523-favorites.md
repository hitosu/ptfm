# Proposal: FAVORITES, cartridges of favourite instruments

Status: **settled** (2026-10-31); its specs are written when the work on it starts, and lead from then on.

**FAVORITES** collects the instruments a player reaches for most, from any cartridge, in one place: browsed
with PRESETS, reached from any screen with one combination, and played as if picked in their own cartridges.
A favourite is a bookmark, not a copy: what is played, recorded or written always carries the instrument's own
number, so no song ever depends on a FAVORITES cartridge, and a favourites list can change freely.

## 1. What a FAVORITES cartridge is

- **A cartridge of references:** each slot names an instrument, `CARTRIDGE:SLOT` (`0B:05`), of any other
  cartridge: any engine, built-in or the user's, a FUSION slot too. It holds no sound of its own, so one
  FAVORITES cartridge mixes every engine. A favourite never names another favourite.
- **128 slots,** like the largest instrument cartridges.
- **The current place and the current instrument:** with a FAVORITES cartridge current, the cursor's place is a
  favourite (`FB:07`) and the current instrument is that favourite's source (`0B:05`). The keys play the source;
  REC, RECORD LIVE, LOOPS, a cell written in the EDITOR and the footer's left all take the source's number. On an
  empty or a missing favourite the current instrument stays the last source picked: the keys go on playing it and
  REC writes it. When the favourite at the cursor changes (EDIT, PASTE, REVERT, a reference rewritten), the current
  instrument follows it, unless it became empty or missing. Nothing ever takes `FB:07` as an instrument.
- **A favourite only refers; nothing refers to a favourite.** No record holds a FAVORITES cartridge's number or a
  favourite's place: not a cell, a song, the loops' table, a FUSION slot, DJ's setup, the MIDI map, nor the
  settings' current instrument at the last SAVE, which keeps the source too (after a start the keys play `0B:05`,
  its own cartridge current). So a FAVORITES cartridge or its slots can be moved, swapped, cloned, emptied or
  deleted without a question and without rewriting anything.
- **Several of them:** the built-in one (below) and any number of the user's own, made with NEW as other
  cartridges.

## 2. The built-in FAVORITES, `FB`

- **The firmware's own, empty,** at `FB` in the range kept for built-in instruments
  ([../files/instruments.md](../files/instruments.md#built-in-instruments)), so it is there from the first start
  and after FACTORY RESET.
- **A changed built-in like the others** ([../ui/saving.md](../ui/saving.md#fws)): once something is added and
  saved, it is a record in the user area under `FB`, its ID no longer brown; BACK TO BUILT-IN empties it again.
  Emptied by REMOVE, it equals the firmware's own, so SAVE deletes its record, as the EDITOR's own pattern's is
  deleted when emptied. It never moves; CLONE makes a copy at a user number; DELETE takes it away as it takes any
  built-in cartridge ([202610311848-editor-instruments.md](202610311848-editor-instruments.md), Deleting a built-in
  cartridge), until FACTORY RESET or the EDITOR page's RESTORE.
- Named `FAVORITES`.

## 3. The record

Kind **0x07**, version 1: a cartridge kind, the seventh sharing the cartridges' one number space
([../files/store.md](../files/store.md#a-record): its "six cartridge kinds" become seven there and in
[../editor.md](../editor.md); [../files/instruments.md](../files/instruments.md#a-cartridge-record)'s kinds
0x01-0x07).

| Bytes | Field |
|---|---|
| 0-8 | name, 12 characters, as every cartridge's |
| 9 | slots stored: up to the last one used |
| 10- | the slots, 3 bytes each: the source's cartridge; its slot (`FF`: an empty slot); a spare byte, 0 |

A full one is 394 bytes. Its changes are held as any cartridge's, a slot a piece
([../files/ram.md](../files/ram.md)): about 1.5 KB of the edit memory with every slot changed. Its properties
(GLO) are any cartridge's, its TYPE `FAVORITES`.

**An older firmware** does not know the kind: it keeps these records byte for byte, as every record it does not
know ([../files/README.md](../files/README.md#extending)), but it does not see their numbers as taken, so its NEW
may make another cartridge under one, and its compaction may rewrite either record as a newer save. Back on a
firmware that knows the kind, **another cartridge kind under the number always wins:** the FAVORITES record is
left out (nothing refers to it) and the next SAVE writes its deletion
([../files/store.md](../files/store.md#power-on) gains the rule).

## 4. On the INSTRUMENTS screen

**Browsing** ([../ui/screens/instruments.md](../ui/screens/instruments.md)):

```
INSTRUMENTS                          1/8
----------------------------------------
FB FAVORITES     FAVORITES 7/128
 00 0B:05 BRASS        08 ----------
 01 F0:03 E.PIANO      09 ----------
 02 F8:12 STRINGS 2    0A ----------
 03 01:00 KICK         0B ----------
 04 0C:07 MISSING      0C ----------
 05 F9:21 COIN         0D ----------
 06 F4:02 CHOIR        0E ----------
 07 ----------         0F ----------
----------------------------------------
...      the source instrument, in detail, as its own cartridge shows it
0B:05 BRASS JUNO            FB FAVORITES
```

| Element | x, y | Font | Shows |
|---|---|---|---|
| the cartridge line | 0, 17 | S | `FB FAVORITES`, the type `FAVORITES`, used / size (`7/128`), as any cartridge's; drawn in T when longer than its 30 characters (a 12-character name with the type and `128/128`) |
| slot *k*'s index | x + 2, y (the slots' grid as any cartridge's) | T | `00`-`7F` |
| its source | x + 20, y | T | `0B:05` |
| its source's name | x + 56, y | T | the name, 10 characters, whole; `MISSING`; `----------` when empty |

- **Colours:** the index dark grey, the source light grey, the name in the source engine's colour, the cursor's
  line white; a missing one's source and `MISSING` grey, as a reference to nothing is drawn
  ([202610311848-editor-instruments.md](202610311848-editor-instruments.md), A reference to nothing); an empty slot
  as in any cartridge.
- **Missing:** a source that is gone (its cartridge deleted, its slot emptied, or its number now a FAVORITES
  cartridge's) plays nothing; the detail below is empty. A built-in source is missing while its slot is emptied by
  a change or its built-in cartridge is deleted.
- **The colour of FAVORITES:** light grey, the colour of no engine, as the cartridges mix every engine: the type
  in the cartridge lists, the cartridge line, the footer's right, the EDITOR page's icon
  ([../ui/colours.md](../ui/colours.md) gains it). Each favourite's name keeps its source engine's colour.
- **The detail below** shows the source instrument as its own cartridge shows it.
- **The footer:** its left names the current instrument as on every screen (`0B:05 BRASS JUNO`,
  [../ui/frame.md](../ui/frame.md#the-footer)), its right the cartridge (`FB FAVORITES`). PRESETS steps through
  the favourites, skipping empty and missing ones.
- **An empty slot:** `EMPTY SLOT: EDIT PICKS AN INSTRUMENT` (in place of `EMPTY SLOT: SEL MENU, INIT OR PASTE`).

**EDIT edits the favourite,** which instrument the slot names, never the instrument itself (that is edited in
its own cartridge):

```
INSTRUMENTS EDIT
----------------------------------------
FAVORITE FB:07
SOURCE 0B:05 BRASS
K1: CARTRIDGE  PRESETS: INSTRUMENT

...      the picked instrument, in detail, as its own cartridge shows it
----------------------------------------
0B:05 BRASS JUNO            FB FAVORITES
```

- the title `FAVORITE FB:07` cyan at 4, 20 (T), `SOURCE` dark grey and the source as the list shows it at 4, 33,
  the hint at 4, 46 as INSTRUMENTS' hints are drawn; the picked instrument's detail from y 100, as browsing shows
  it;
- **the current instrument** while editing is the one picked: the keys play it (ARP too), and the footer names
  it; EDIT keeps it, HOME drops it and the favourite's source is current again;
- **K1** turns the source's cartridge over every cartridge with an instrument (FAVORITES cartridges and empty
  ones left out), wrapping, at its first instrument; from a missing source it starts at the source's number if
  that cartridge is there, else at the first. While it turns, the cartridge list shows over the screen
  ([../ui/dialogs.md](../ui/dialogs.md#the-cartridge-list)), titled `CARTRIDGES`, listing the cartridges K1
  reaches, the picked one highlighted, closing a second after the last click as PRESETS' instrument list does;
  it shows always, PRESETS LIST ON or OFF (that setting is PRESETS' list's alone);
- **PRESETS** and **SELECT** step through that cartridge's instruments, from its first when the source is
  missing, PRESETS' instrument list showing as they turn, while SETTINGS' PRESETS LIST is ON
  ([../ui/dialogs.md](../ui/dialogs.md#presets-instrument-list), whose "not on INSTRUMENTS" gains this
  exception);
- **ENV** opens the same cartridge list as K1's; ENV again picks the highlighted one;
- **EDIT** again keeps the change, **HOME** drops it, as in every editor. EDIT on an empty slot starts here, at
  the current instrument (so a slot can be filled without leaving FAVORITES; instruments.md's `EMPTY SLOT:
  NOTHING TO EDIT` is not shown in a FAVORITES cartridge);
- ALGORITHM and LFO do nothing here, GLO shows the cartridge's properties as while browsing, and SEL opens no
  menu: what a favourite has to edit is its source alone.

**The SEL menus:**
- **On an instrument slot that holds one** (browsing and edit mode, `SLOT 01:00` / `SLOTS 00-05`): **ADD TO
  FAVORITES**, right after MARK while browsing (first with slots marked), and in edit mode first, after EDIT
  PATTERN where that is listed.
  - Listed only while a FAVORITES cartridge exists (the built-in `FB` can be deleted).
  - With one FAVORITES cartridge it is an action and adds there at once. With several it is a group of them
    ([../ui/dialogs.md](../ui/dialogs.md#levels)), by the levels' rules: titled `ADD TO FAVORITES` (the slot
    before it would pass 23 characters), BACK, then `FB FAVORITES` and the user's own in the lists' order, the
    highlight on the last one used, else on `FB FAVORITES`.
  - It takes the first empty slot; marked slots each take one, in order, empty ones and those already there
    skipped. Toasts: `ADDED TO FB:07` (the first one added); `ALREADY IN FB:07` (nothing to add: the first one
    already there); `FAVORITES FULL` (not enough empty slots: nothing added).
- **NEW CARTRIDGE** in the INSTRUMENTS screen's slot menu too, while browsing (FAVORITES' own included), after
  AUTO LEVEL (REMOVE in FAVORITES), REVERT still last: a group titled `NEW CARTRIDGE` (the slot before it would
  pass 23 characters): BACK, DX7, JUNO-106, TB-303, CHIP, SAMPLER, FUSION, FAVORITES. The cartridge is made as the
  cartridge list's NEW makes it, at the number after the last of the user's cartridges, and opened (`CARTRIDGE 11
  MADE`). The cartridge list's NEW gets **FAVORITES** last; a new FAVORITES cartridge is named `MY FAVORITES`
  (`NEW FAVORITES` is longer than a cartridge's 12 characters).
- **In a FAVORITES cartridge,** `SLOT FB:07` / `SLOTS FB:00-05`: MARK, COPY, PASTE, MOVE, SWAP, **REMOVE**, NEW
  CARTRIDGE, REVERT (only while the slot has something unsaved, as in every cartridge).
  - **REMOVE** empties the slot, or every marked one: the favourite goes, its source stays; no question.
  - **COPY** copies references, 4 at most as in every cartridge; **PASTE** writes them as they are, into a
    FAVORITES cartridge only (a favourite pasted twice is allowed, as PASTE allows any copy; ADD TO FAVORITES is
    the one that skips those already there). A FAVORITES copy pasted elsewhere, and an instrument's copy pasted
    into FAVORITES, are refused as PASTE refuses a copy of another type: `COPIED FROM FAVORITES: NOT HERE`,
    `COPIED FROM DX7: NOT HERE`; instruments.md's toasts gain both. ADD TO FAVORITES is the way in.
  - **MOVE and SWAP** as in any cartridge ([../ui/dialogs.md](../ui/dialogs.md#move)): MOVE to an empty slot
    only, none in a full one (`NO EMPTY SLOT: SWAP INSTEAD`); nothing refers to a favourite's place (section 1),
    so they ask nothing.
  - No INIT, RENAME or AUTO LEVEL: a favourite has no sound or name of its own.
- **The cartridge's own menu** (`CARTRIDGE FB` in the cartridge list): as a built-in's (NEW, CLONE, RENAME, DELETE,
  BACK TO BUILT-IN once changed) or as the user's cartridges' (NEW, CLONE, MOVE, DELETE, RENAME), REVERT last while it
  has something unsaved, AUTO LEVEL ALL left out; MOVE and DELETE of a FAVORITES cartridge ask nothing about
  references (none point at it).

## 5. FAVORITES everywhere else

- **SEL + ENV: SEL held, then ENV pressed,** acting at ENV's press, switches the current cartridge to the built-in
  FAVORITES, at the favourite last used there (the first one after a start). With the built-in FAVORITES current,
  however it became current, SEL + ENV goes back to the place it held before: the cartridge and the slot, and so
  the instrument.
  - **An exception to the combinations' either-order rule** ([../ui/controls.md](../ui/controls.md#buttons-tap-hold-and-layers)
    gains it): only SEL held first combines; SEL tapped first and then ENV is SEL's tap, then ENV's own job; ENV
    alone acts at once, as now, and waits for no grace period. ENV held past the hold delay without SEL is still
    the EDITOR's pipette.
  - **Where:** wherever SEL + PRESETS works (not on DJ, nor over a question, a name being typed or an overlay),
    and not in an editor's edit mode (INSTRUMENTS' EDIT, a favourite's edit): there it is refused, the button
    blinking. The header names the cartridge as SEL + PRESETS does
    ([../ui/controls.md](../ui/controls.md#knobs); the key map gains the row; [../ui/leds.md](../ui/leds.md):
    ENV dim while SEL is held wherever SEL + ENV works).
  - With the built-in `FB` deleted it goes to the first FAVORITES cartridge left in the lists' order. With no
    favourite in any FAVORITES cartridge it does not switch: `NO FAVORITES YET`. A shortcut: the tap route is the
    cartridge lists.
- **First in the cartridge lists,** one order everywhere: ENV's list, PRESETS' cartridge list, K1's order on
  INSTRUMENTS, LOOPS' list for the next loop's instrument, MIDI's bank select: the built-in one first, then the
  user's own by number, then the other cartridges as now. A FAVORITES cartridge afloat (MOVE) is listed among the
  FAVORITES cartridges, under the number it would take.
- **An empty FAVORITES cartridge picked** from a list (as SEL + PRESETS or ENV pick a cartridge "at its first used
  slot") has its cursor on its first slot and keeps the current instrument (section 1); on LOOPS, as any empty
  cartridge there: `CARTRIDGE FB IS EMPTY` ([../ui/screens/loops.md](../ui/screens/loops.md)).
- **The first instrument there is** (the settings' fallback when the instrument saved at the last SAVE is gone,
  [../files/settings.md](../files/settings.md)) skips FAVORITES cartridges; a saved current instrument naming a
  FAVORITES cartridge's number counts as gone.
- **PRESETS on every screen,** with a FAVORITES cartridge current, steps through its favourites; the header names
  the source, as any instrument, and PRESETS' instrument list shows the favourites it steps through as INSTRUMENTS
  lists them (`07 0B:05 BRASS`; empty and missing ones left out, as PRESETS skips them).
- **MIDI** ([../connections.md](../connections.md)): a program change with a FAVORITES cartridge current picks
  its *n*-th used slot, counted from 0, as in any cartridge (a missing one counted, keeping the current
  instrument); **bank select** counts the cartridges in the lists' one order, the FAVORITES cartridges first (bank
  0 the built-in FAVORITES).
- **The EDITOR's TAKE ITS INSTRUMENT** (the pipette) takes a cell's instrument, the source's number as the cell
  holds it; a cell naming a FAVORITES cartridge's number (section 6) names no instrument: `NO INSTRUMENT HERE`.
- **The current place** joins what navigation keeps ([../ui/navigation.md](../ui/navigation.md): "the cursor on
  INSTRUMENTS"): the cartridge and slot the cursor last stood on, a favourite's too.

## 6. References

A favourite is a reference, kept right as the others are ([../files/references.md](../files/references.md)), and
only ever the one referring:
- **What refers to what** gains (here and in [../ui/saving.md](../ui/saving.md)'s list): a FAVORITES slot to an
  instrument (cartridge:slot). Nothing refers to a FAVORITES cartridge or slot (section 1). **Finding them** reads
  the FAVORITES cartridges too.
- **A reference that names a FAVORITES cartridge names nothing:** a cell, a loop or a favourite left naming a
  number that a FAVORITES cartridge took later (after a DELETE, or under an older firmware) is grey, plays as a
  silent engine ([202610311848-editor-instruments.md](202610311848-editor-instruments.md), section 4), and is
  listed by CHECK REFERENCES.
- **MOVE or SWAP** of an instrument or a cartridge, answered YES, rewrites the favourites that name it in the
  same save. Answered NO, they keep naming the same place, as cells do: after a MOVE that is nothing, after a SWAP
  the instrument now there. **DELETE never rewrites a reference**
  ([202610311848-editor-instruments.md](202610311848-editor-instruments.md), A reference to nothing): the
  favourites naming what is deleted keep naming its place, `MISSING` in grey, playing nothing, skipped by PRESETS,
  and play again when an instrument is put there.
- **The questions count them:** a favourite is a use in `... IS USED 3 TIMES` (MOVE, SWAP, DELETE) and in
  `UPDATING 3 REFERENCES`.
- **SETTINGS' TOOLS** ([../ui/screens/settings.md](../ui/screens/settings.md)): CLEAN UP's UNUSED INSTRUMENTS
  are those no cell plays, no loop and no favourite names, and a FAVORITES cartridge is never listed; AUTO LEVEL
  ALL leaves FAVORITES cartridges out; CHECK REFERENCES lists a favourite whose source is gone as FUSION's are
  listed: `FAVORITE FB:07: 0B:05`.
- A built-in cartridge never moves, but its slots do (MOVE and SWAP on the FM-1, rearranging on the EDITOR page,
  [202610311848-editor-instruments.md](202610311848-editor-instruments.md) section 3): a favourite of one follows them
  as any favourite does.

## 7. The EDITOR page

- **A FAVORITES cartridge is an item** like any cartridge ([../editor.md](../editor.md)): READ, WRITE, UPLOAD
  DISK, DOWNLOAD DISK and the disks carry kind 0x07; its kind is among the TABLE's groups and `+ NEW`'s kinds, a
  new one named `MY FAVORITES`, its kind shown as `FAVORITES` in DETAILS.
- **Its tab edits it:** each slot's source picked (a cartridge, then one of its instruments), slots removed,
  moved and swapped, the cartridge renamed; the preview plays the source. On the FM-1 panel a favourite is listed
  as the FM-1 lists it (`07 0B:05 BRASS`); on the TABLE, which has no numbers, by its source's name and its
  source's cartridge's name.
- **Moving it to the other panel takes every cartridge it names along,** as a song takes its cartridges (the
  built-in ones excepted: every PT/FM carries them; one deleted on the FM-1 panel leaves the favourite grey there,
  with the status line a song's move gives, [202610311848-editor-instruments.md](202610311848-editor-instruments.md)
  section 4); renumbering rewrites its references; it is reused by hash as
  any item. Nothing takes a FAVORITES cartridge along (nothing refers to it).
- **DELETE:** a FAVORITES cartridge never goes along with what it names: deleting an instrument or a cartridge
  leaves the favourites naming it as they are, `MISSING` in grey, as on the FM-1; a FAVORITES cartridge's own DELETE
  never takes its sources
  (ALSO WHAT ONLY IT USES leaves them); and a cartridge a favourite names is still used, so deleting a song does
  not take it as one only that song used, as CLEAN UP keeps it on the FM-1.
