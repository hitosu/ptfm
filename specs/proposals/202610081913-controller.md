# Proposal: the controller firmware

Status: **settled** (2026-10-08); the spec: [../controller.md](../controller.md), which leads from now on.

**The controller** is a small firmware of its own, apart from PT/FM's, that turns the FM-1 into a
USB-MIDI controller. Its first use is to work the virtual FM-1 (the playground now, the emulator later)
from the real panel; it also plays any synth or DAW. Its screen shows the MIDI it sends. It lives in
`controller-fw/`.

It has two modes:
- **mirror** (channel 16): every control sends one fixed message, and the virtual FM-1 turns it back
  into the same control; the page drives the FM-1's LEDs in return;
- **musical** (channel 1): a keyboard controller for synths and DAWs: notes with an octave shift,
  knobs as values, Program Change, a play button for DAWs.

**The page** below is the one showing the virtual FM-1: the playground, later the emulator.

## 1. The modes and power-on

- **Power-on starts in the mode used last.** A fresh install starts in mirror (5.4).
- **OCT- and OCT+ held while switching on** flip the mode, and the new mode is saved.
- **OCT- alone** while switching on is USB rescue, as in every firmware (5.6).
- **Controls held at power-on send nothing until they are let go,** so the OCT- and OCT+ that flipped
  the mode never reach the page.

## 2. Mirror mode

Channel 16, both ways.

### 2.1 From the FM-1

| Control | Message |
|---|---|
| a key, F3-G5 (k = 0-26) | Note On 53 + k, velocity 127; Note Off 53 + k, velocity 0, when let go |
| a button (id 0-13) | CC 102 + id: 127 pressed, 0 let go |
| a knob (id 0-6) | CC 20 + id, relative: 1-63 that many clicks clockwise, 127-65 1-63 clicks back |
| MASTER | CC 7, 0-127 |

- **The ids are the firmware's:** buttons OCT- 0, OCT+ 1, FX 2, SEL 3, ENV 4, LFO 5, EDIT 6, GLO 7,
  HOME 8, SAVE 9, ARP 10, SEQ 11, PLAY 12, REC 13; knobs SELECT 0, ALGORITHM 1, K1-K4 2-5, PRESETS 6.
- **A knob's message carries its clicks since its last one,** at most one a millisecond per knob.
- **MASTER is sent when it moves past a threshold** above the pot's noise, so a still MASTER sends
  nothing.

### 2.2 To the FM-1: the LEDs

| LED | Message |
|---|---|
| key k | Note On 53 + k, velocity = level (a Note Off is level 0) |
| button id | CC 102 + id, value = level |
| PLAY's green LED | CC 116 |

- **Level:** 0 off, 1-63 dim, 64-127 lit.
- **Blinking** is the page sending changes.
- **In mirror mode the FM-1 lights nothing by itself.**

## 3. Musical mode

Channel 1.

| Control | Sends |
|---|---|
| keys | notes, velocity 100 |
| OCT- / OCT+ | nothing: the keys an octave down / up, -3 to +3; both together: back to 0 |
| K1-K4 | CC 74 (cutoff), 71 (resonance), 73 (attack), 72 (release), 0-127 |
| SELECT | CC 1 (modulation), 0-127 |
| ALGORITHM | CC 21, 0-127 |
| PRESETS | Program Change, 1-128 |
| MASTER | CC 7, 0-127 |
| PLAY | CC 114: 127 pressed, 0 let go; and MMC Play (`F0 7F 7F 06 02 F7`), then MMC Stop (`F0 7F 7F 06 01 F7`), in turn |
| the other buttons | CC 102 + id, as in mirror mode (2.1): FX 104, SEL 105, ENV 106, LFO 107, EDIT 108, GLO 109, HOME 110, SAVE 111, ARP 112, SEQ 113, REC 115; 127 pressed, 0 let go |

- **A button has the same CC in both modes** (102 + its id), only on another channel; 102 and 103 (OCT-
  and OCT+) are unused here.
- **The FM-1 keeps the values:** K1-K4 start at 64, SELECT and ALGORITHM at 0, the program at 1, the
  octave at 0, stopped. They start so at every power-on, and no value is sent until its control moves.
- **A click moves a value by 1;** clicks under 40 ms apart move it by 2, under 20 ms by 4 (10). Values
  stop at 0 and 127. PRESETS moves the program by 1 a click, and stops at 1 and 128.
- **PLAY reaches the most DAWs this way:** those that follow MIDI Machine Control (MMC) start and stop
  with no setup; the others learn CC 114 as their play button. The FM-1 sends no MIDI clock, so MIDI
  Start and Stop would move nothing, and gear set to follow a clock would wait for one.
- **A key's Note Off goes to the note its Note On sent,** whatever the octave is by then.
- **The LEDs:**
  - keys: lit while held;
  - OCT- or OCT+: the octave shift, dim at 1, lit at 2, blinking at 3, as PT/FM's OCT;
  - PLAY: green from an MMC Play to the next MMC Stop;
  - the other buttons: lit while held.
- **When USB comes up,** the FM-1 sends All Notes Off (CC 123) on channel 1: Note Offs may have been
  lost while it was down.

## 4. Finding each other

SysEx under the non-commercial manufacturer ID 7D, then `PTC`:

| | Bytes |
|---|---|
| the page asks | `F0 7D 50 54 43 01 F7` |
| the FM-1 answers | `F0 7D 50 54 43 02 <mode> <version> F7`: mode 0 mirror, 1 musical; version 1 |

- **The page asks** when its MIDI is turned on and whenever a MIDI port appears, on every output: ID
  7D is for non-commercial use, so other gear ignores the question.
- **The FM-1 also sends its answer unasked** whenever USB comes up: a hello.
- **Port names do not matter.** The page pairs the input that answers with the output of the same
  name. A computer may keep showing an older name for the device; pairing does not depend on it.
- **At every answer the page** lets go of every control it holds from MIDI and, in mirror mode, sends
  every LED once.
- **After every answer in mirror mode, the FM-1 sends its state:** MASTER's position, and every key
  and button held at that moment. The page then starts from the panel as it is, whenever it pairs.

## 5. The firmware

### 5.1 The device layer

- **The device layer is one already proven on the FM-1** (GPL-3.0-only), cut to what the controller
  uses:
  - the hardware layer, start-up and linker script;
  - USB-MIDI, the update protocol and the update loader;
  - the rescue screen and the boot guard;
  - the LCD and its canvas;
  - the packager and the install page's scripts.
- **Everything else is removed,** not switched off: USB audio, the serial console, the audio output,
  the MIDI jack, the layer's storage (projects, presets, settings), and every function nothing calls. The
  flash driver stays, for the mode's record (5.4).
- **The update loader stays byte for byte the one the installers know;** they require it.
- **The layer's files keep their licence lines;** where one is changed, PT/FM's go below.
- **The USB name is "FM-1 Controller".** The installers find the FM-1 by "FM-1" in its name.

**Ours:**
- `ctl.c`, portable, with no hardware: inputs to messages, LED messages to LED states, musical mode's
  values. The host tests run it.
- `screen.c`: the monitor (section 6).
- `controller.c`: power-on, the mode, the main loop, the interrupts.

### 5.2 Time

- **TIMER5 runs at 10 kHz:** each tick scans the matrix; every 5th polls USB (2 kHz); every 10th runs
  `ctl_tick` (1 kHz), which:
  - compares the keys and buttons with what was sent;
  - takes the knobs' clicks and MASTER;
  - queues the messages for USB and for the screen's log;
  - applies the LED messages that came in.
- **A press reaches USB 2-4 ms after the contact closes,** whatever the screen is doing: the keys'
  debounce (1.1-2.2 ms), then up to 1 ms to `ctl_tick` and 0.5 ms to the USB poll. A release takes
  about 9 ms more: the debounce waits that long against a contact chattering open.
- **The main loop** reads MASTER's ADC (smoothed; the interrupt decides what to send), draws the
  screen and retries USB.
- **The out queue holds 256 USB-MIDI packets.** While USB is down, or the queue is full, messages are
  dropped and counted (LOST, section 6).

### 5.3 No sound

The codec is never started; its control lines stay as they are at power-on (10).

### 5.4 The flash

- **The mode is the controller's only write.** A 16-byte record (marker, mode, CRC-32) at the start of
  the first 4 KB block after the firmware's end, inside the firmware slot; written raw, read with a
  direct read.
- **Written only at a power-on that flips the mode,** before USB starts: an erase (17 ms on the FM-1)
  and a program (about 2 ms).
- **A record that fails its check** (a torn write, an erase cut short, another firmware's data) means
  mirror.
- **If the write fails,** the flipped mode holds until power-off, and the log says `MODE NOT SAVED`.
- **Every install wipes the slot,** so a fresh install starts in mirror. Nothing outside the slot is
  written: PT/FM's records and other firmwares' data stay as they are.

### 5.5 Identity and pages

- **Package identity `FM-1_7100`** (the installers accept only `FM-1_<digits>`).
- **`dist/controller-install.html`** installs it (Chrome or Edge, Web MIDI), self-contained;
  `dist/controller.fwsc` is the package for other installers. Both are committed: PT/FM's `dist/`
  holds every firmware's built files, each under its own names.

### 5.6 Updates and rescue

As every firmware:
- the installer's SysEx is answered in both modes;
- OCT- alone at power-on, or two failed boots in a row, start USB rescue.

## 6. The screen: a MIDI monitor

PT/FM's look: the soft EGA palette on black (the UI proposal, 4.1:
[202610072229-ui.md](202610072229-ui.md)), the Terminus fonts; the 6x12 font, 40 columns.

```
CONTROLLER                  MIRROR CH16    header, 16 px
──────────────────────────────────────────
USB ON   PAGE OK   SENT 1234   LOST 0      status, 12 px
──────────────────────────────────────────
K1        CC 22   +3          BF 16 03     the log: 17 lines in mirror mode,
C-4       NOTE ON   127       9F 3C 7F     15 in musical; the newest at the bottom
C-4       NOTE OFF            8F 3C 00
PLAY      CC 114  127         BF 72 7F
MASTER    CC 7    96          BF 07 60
──────────────────────────────────────────
OCT +1  K1 64  K2 64  K3 64  K4 64         footer, musical mode only:
MOD 0   CC21 0  PRG 1   STOPPED            the values the FM-1 keeps
```

- **A log line:** the control as printed on the panel (a key as the note it sent, `C-4`), the message
  in words, the bytes in dark grey.
- **Colours:** notes white, CCs light blue, Program Change yellow, MMC Play and Stop green, the
  handshake's SysEx magenta.
- **A turn does not flood the log:** while a knob's or MASTER's line is the newest, it is updated in
  place: in mirror mode the clicks add up (`+3`, `+12`), in musical mode it shows the value (`= 87`).
- **The status line:**
  - USB: ON, OFF, or ASLEEP while the host is suspended;
  - PAGE: OK once a page has asked (section 4) or sent an LED since USB came up (mirror mode only;
    a page closed later is not seen);
  - the messages sent and lost.
- **The LED messages that come in are counted, not logged;** blinking would flood the log.
- **After a power-on that flipped the mode,** the first log line says `MODE MUSICAL` or `MODE MIRROR`.
- **Only changed lines are drawn,** about 1 ms each.

## 7. The page: `panel/midi.js`

In `panel/`, so the playground has it now and the emulator later.

- **A MIDI button** on each page (the playground's beside its SIZE buttons) turns it on; Chrome asks
  once for MIDI with SysEx.
- **The page remembers it is on** (the browser's storage), so after a reload it pairs again with no
  click. The sound still waits for a click on the page: a browser starts audio only after one, and a
  MIDI message does not count. The button's own click starts it.
- **A label beside it** shows the state: `MIDI: OFF`, `LOOKING`, `FM-1 MIRROR`, or
  `FM-1 MUSICAL (ignored)`.
- **Pairing** as section 4. A hello (USB came up, a power-on) pairs again, so unplugging and plugging
  back just works.
- **The paired port's messages are the panel's only:** the page never passes them on as MIDI to
  anything else.
- **One page at a time:** two open pages would both pair and both drive the LEDs.

**Mirror mode's messages become the panel's own controls:**

| From the FM-1 | On the virtual FM-1 |
|---|---|
| keys and buttons | `press(id, "midi")` / `release(id, "midi")`: a control held from the mouse and from MIDI is let go only when both let go |
| a knob's CC | that many clicks of +1 or -1, as the mouse wheel gives |
| CC 7 | MASTER at value / 127 |

- **The LEDs go back:** every change of the panel's `led(id, level)` is sent: lit 127, dim 32, off 0;
  PLAY's green LED on CC 116. Only changes are sent; at every pairing all of them once.
- **When the FM-1 goes away** (its port disconnects, or a hello comes), every control held from MIDI
  is let go.
- **In musical mode** the page does nothing with the FM-1's messages.
- **`panel/device.js` gains:** `turn(id, step)` (a knob's click from code), `setMaster(v)`, and an
  `"led"` event when an LED changes.

## 8. Folders

```
controller-fw/
  README.md     the controls, the protocol, installing
  hal/          the device layer's hardware layer, cut
  loader/       the update loader the installers know
  src/          the device layer's usb.c, ota.c, lcd.c, gfx.c, ... cut; PT/FM's: controller.c, ctl.c, screen.c
  tools/        build.py, fm1pkg_make.py
  web/          the install page, fm1ota.js, fm1pkg.js
  tests/        host tests
```

- **Built files:** `dist/controller.fwsc` and `dist/controller-install.html` (committed); the rest in
  `build/controller/` (ignored).

- **The build:** `controller-fw/build.sh`. `JIELI_TOOLCHAIN` points at JieLi's toolchain
  and `AC79_SDK` at the AC79 SDK (V1.2.1), whose three files in the package are checked by SHA-256.
- **The build's checks:** the app fits the slot; RAM within the limit; register access only in
  `hal/`; `.ram_text` makes no calls.
- **The fonts** come from `assets/fonts/`; `tools/gen_fonts.py` gains a C output.
- **The page's part** is `panel/midi.js`, with its test in `tests/`.

## 9. Testing

**On the PC:**
- **`ctl.c`,** built with gcc and its sanitizers: scripted inputs give exactly the expected bytes:
  - keys, chords, buttons, slow and fast knob turns, MASTER sweeps;
  - the octave changed while keys are held;
  - controls held at power-on, the mode flipped;
  - LED messages in give the right LED states;
  - the mode record read back after a good write, a torn write, an erased block and other data.
- **The screen:** PNGs of both modes with a scripted log, looked at; partial redraws equal full
  redraws, pixel for pixel.
- **`panel/midi.js`** under Node with a fake Web MIDI: pairing and pairing again, every mirror message
  on its control, LED changes as bytes, a disconnect letting everything go.
- **One table of test vectors** (control, bytes), `controller-fw/tests/vectors.json`, is read by both
  tests, so the two sides cannot drift apart.
- **The build's checks** (section 8).

**On the FM-1:**
- the speaker silent;
- every control working the playground, and the LEDs following it;
- how immediate it feels;
- OCT- with OCT+ flipping the mode, and the mode kept across power-cycles;
- another firmware's data intact after the controller: a project saved by it, the controller installed
  and its mode flipped, that firmware installed again, the project still there;
- musical mode in a DAW.

## 10. Still open

- **The speaker with the codec never started:** silent, or a hum. If it hums, the codec is started and
  sent silence.
- **The knobs' acceleration** (40 ms and 20 ms, 2 and 4 a click): to tune on the FM-1.
