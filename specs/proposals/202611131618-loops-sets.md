# Proposal: LOOPS sets

Status: **settled** (2026-11-13); its specs are written (2026-11-16) and lead from now on; the sets' list draws as the
song list (in 8 × 16, 10 lines), as every list that fits does since the bigger lists; since 2026-11-18 its two items
come before SAVE TO PATTERN and LOAD FROM PATTERN in the SEL menu (the whole of LOOPS first), not after them. It
changes [../ui/screens/loops.md](../ui/screens/loops.md), [../ui/dialogs.md](../ui/dialogs.md),
[../files/loops.md](../files/loops.md), [../files/store.md](../files/store.md) (the table of kinds),
[../files/references.md](../files/references.md), [../files/disk.md](../files/disk.md), [../editor.md](../editor.md).

LOOPS keeps one working area: its record (kind 0x22), kept by SAVE like any change. SAVE TO PATTERN and LOAD FROM
PATTERN go through a pattern, which keeps the notes but not LOOPS itself: the loops' instruments by lane, their
repeats, SHIFT, mutes, mixes, the setup and LOOPS' own FX setup. **A set** is a copy of the whole working area, kept
under a number of its own, to come back to later: several jams on one FM-1.

## 1. What a set holds

Everything LOOPS' record keeps ([../files/loops.md](../files/loops.md#what-is-kept)): the loops and their notes, the
length, the setup (TEMPO, TICKS A ROW, the grid, SWING, QUANTIZE, MONO LEGATO, COUNT-IN, the keys' mode, VIEW, K1-K4's
jobs, a new loop's defaults), every loop's mix and mute, LOOPS' own FX setup with its METRONOME, the selected loop;
**plus the solos**, which the working area never saves. Not the stage (a load leaves it as it is, fitted to the
length the set brings), nor NEW (the next loop's own mix, RAM's: the set's defaults again after a load, as after LOAD
FROM PATTERN).

## 2. On LOOPS

The SEL menu gets two items after LOAD FROM PATTERN: **STORE AS A SET** and **LOAD A SET** (LOAD A SET listed while a
set exists).

- **STORE AS A SET** opens the sets' list (section 3) titled `STORE THE LOOPS AS`, `NEW` first and picked (the first
  free number); SEL takes it, or a set, asking first (`SET 03 HOLDS LOOPS` / `REPLACE IT WITH THESE?`). It copies the
  working area as it stands (its unsaved changes included) with the solos into the set: an edit like SAVE TO
  PATTERN's pattern, kept in the flash by SAVE, dropped by REVERT ALL (`LOOPS STORED AS SET 03`). A new set is named
  `LOOPS 03` (its number). The loops go on as they were. Refused when the edit memory cannot hold it (`MEMORY FOR
  EDITS IS FULL`), as SAVE TO PATTERN is.
- **LOAD A SET** opens the list titled `LOAD INTO LOOPS`; SEL takes the highlighted set, asking first while LOOPS has
  loops (`REPLACE THE LOOPS` / `WITH SET 03?`). It copies the set into the working area: an edit, which SAVE keeps and
  REVERT (LOOPS' or ALL) undoes, nothing written to the flash until SAVE; the solos as the set holds them; NEW the
  set's defaults; the stage stays, fitted to the set's length (as LOAD FROM PATTERN fits it). **The loops stop** if
  they played, at their start, and wait for PLAY (stopped, it loads at once, as ever). While a song records (RECORD
  LIVE), its time runs on: the loops are left silent at their start, PLAY bringing them on, as LOAD FROM PATTERN does.
  Toast `SET 03 LOADED`.

## 3. The sets' list

An overlay as the pattern list ([../ui/dialogs.md](../ui/dialogs.md#the-pattern-list)), its panel, highlight and
scrolling (13 lines):

```
+--------------------------------------+
|LOAD INTO LOOPS                       |   the title, T
| NR  NAME              LOOPS  BARS    |   the column heads
|[03  SUNDAY JAM          6     4     ]|
| 04  LOOPS 04           16     8      |
+--------------------------------------+
```

- **Each line:** the number `00`-`EF`; the name, 16 characters; how many loops; the length in bars (`4`, or `4.5`
  where the length is not whole bars of the set's own METRONOME).
- **The key that opened it** (SEL) picks the highlighted set; HOME closes it.
- **No preview** (PLAY does nothing here): a set is a whole loop station, heard once loaded.
- **EDIT renames** the highlighted set (text entry, 16 characters); **LFO deletes** it after a question (`DELETE SET
  03?`, OCT+ `DELETE`, OCT- `KEEP`): both edits SAVE keeps. Nothing refers to a set, so neither asks about references.
  The list's last line says it: `EDIT: RENAME  LFO: DELETE` (SEL picks, as the opener).
- Colours as the pattern list's: numbers light grey (white highlighted), names light grey, the counts cyan.

## 4. The record

Kind **0x24**, a LOOPS set, numbers `00`-`EF` (`F0`-`FF` kept for built-in sets, none yet), version 1, in parts as
the loops' record:

| Bytes | Field |
|---|---|
| 0-11 | the name, 16 characters, as a song's ([../files/songs.md](../files/songs.md#the-record)) |
| 12-13 | the solos: bit *i* loop *i* soloed |
| 14-15 | 0 |
| 16- | the loops' record ([../files/loops.md](../files/loops.md#the-record)) as it is, version 4: its head, its table, its streams |

Part 0 holds bytes 0-15 and the loops' record's part 0; the other parts are the loops' record's own (a part holding at
most a head and two streams, the 16 bytes added still leave part 0 within a block: checked by the build). **A set
refers** as the loops' record does: each loop's instrument by cartridge and slot
([../files/references.md](../files/references.md)), so MOVE, SWAP and DELETE of a cartridge ask about a set's loops as
about the working area's, and every reference follows. A version 4 that changes (a later loops record) changes the
set's version with it, the PC side converting both.

## 5. On the EDITOR

Sets are items of their own kind, `LOOPS SETS` among the TABLE's groups (not among `+ NEW`'s kinds: a set is made on
the FM-1), shown as `SET` in DETAILS with its loops, length and tempo; READ, WRITE, the disks, moves (with the
cartridges and samples its loops play, as a song takes its), DOWNLOAD and DELETE as any item; renumbering rewrites
nothing (nothing refers to a set). No tab of its own: its contents are LOOPS' (the FM-1's job). None on the demo disk.

## 6. The playground and the tests

The playground carries the same (its LOOPS SEL menu, the list, the record kind in its store). Tests: the loops tests
(a set stored and loaded back the same, byte for byte, with solos; a load over loops; a load while playing stops;
the stage fitted; NEW the set's defaults; REVERT undoing a load; references followed through MOVE and DELETE), ui3
and the playground's (the menu items, the list, its menu, the questions, the toasts), the EDITOR's (a set read,
written, moved with its cartridges, on a disk).
