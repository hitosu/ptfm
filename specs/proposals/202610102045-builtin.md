# Proposal: built-in instruments, the user area and ROM

Status: **settled** (2026-10-10); its specs are written (section 7's files; the UI's in
[../ui/saving.md](../ui/saving.md#fws)). Kept as the record; the specs lead. Its open points are closed:
ROM became FWS, holding the firmware alone ([202610201630-fws-buffer.md](202610201630-fws-buffer.md)). One
change since: every try to change a thing in ROM
shows a message that ROM is read-only, and every song, pattern, cartridge and sample has MOVE TO ROM in
its menu. Then the numbers: cartridge and pattern numbers `F0`-`FF` are kept for the built-in
instruments, which move there (cartridges `F0`-`FB`, FUSION's patterns `F0`-`F4`); section 2's numbers
below are the first draft's ([../files/instruments.md](../files/instruments.md#built-in-instruments)).

## 1. The idea

The firmware ships with the demo instruments that need little space, and no samples
or demo songs; songs, patterns and everything else come as a disk to upload, into the user area. ROM
is read-only: what is there can be deleted, moved out or copied out. Anything added to ROM becomes
read-only and is lost at a firmware update, which rewrites all of ROM, so moving a thing there is
always the FM-1 user's choice, confirmed. Nothing is created in ROM: read-only, a new thing there would
be meaningless.

- **ROM** is the firmware slot: the firmware, the built-in instruments, and the free part after them.
  Everything in it is read-only.
- **The firmware carries the demo disk's synth instruments:** they cost the user no space.
- **Everything else is a disk:** the demo songs, their patterns, the sampler cartridges and their audio
  are uploaded into the user area, and the user may delete them.
- **The user area** (the fast regions, [../files/store.md](../files/store.md#where-things-go)) holds the
  user's work and whatever was uploaded. Every save goes there.
- **The user may move finished things into ROM's free part,** by choice and confirmed: read-only from
  then on, and erased by a firmware update unless backed up.

## 2. Built-in instruments

- **Which:** the demo disk's eight DX7 cartridges, JUNO-106, CHIP, TB-303 and FUSION with its five
  patterns. **Never samples or songs:** the sampler cartridges, their audio (180 KB), the songs and
  their patterns are only ever uploaded.
- **Their numbers are the demo disk's:** cartridges `01`-`08` DX7, `09` JUNO-106, `0A` CHIP, `0B` TB-303,
  `11` FUSION; FUSION's patterns `D0`-`D4` in the shared pool. The user's own cartridges and patterns
  take the other numbers. The sampler cartridges `0C`-`10` come with the disk.
- **In ROM, so read-only** ([section 5](#5-rom)). They cannot be deleted either: they are the firmware's
  own, and deleting them would free nothing. COPY and PASTE of a slot, and CLONE of a cartridge to a
  free number, make an editable copy in the user area
  ([../ui/screens/instruments.md](../ui/screens/instruments.md)).
- **Frozen once released:** songs refer to them by number (`01:05`), so a built-in instrument's sound
  never changes. A later firmware may add built-in instruments at free numbers, never move, change or
  remove one ([../files/README.md](../files/README.md#extending)).
- **Read in place, as the firmware's own data:** as fast as the user area, and no records, no scan, no
  RAM.
- **Their licences travel with the firmware:** ABOUT and the install page list them.
- **Size:** 42 KB (the synth cartridges 33 KB, FUSION with its patterns 9 KB).

**The firmware slot:**

| | KB |
|---|---|
| The slot (the app at most 581,564 B) | 568 |
| The firmware: estimated before it is written, from the engines, player and effects as built and measured (136 KB) and the UI as the playground has it | ~300 (220-350) |
| The built-in instruments | 42 |
| **Left: ROM's free part, and the firmware's room to grow** | **~225** (175-305) |

## 3. The demo disk, uploaded

- **`dist/demo.ptd`** holds the demo songs, their patterns, the sampler cartridges and their audio. The
  demo disk's sources keep the built-in instruments too (`demo-disk/`); the firmware's build takes them
  from there.
- **Where it goes:** the user area, like anything uploaded.

**The user area, with the whole demo disk uploaded:**

| | Blocks | KB |
|---|---|---|
| The fast regions | 103 | 412 |
| The reserve for saves and compaction ([../files/store.md](../files/store.md#where-things-go)) | −16 | −64 |
| The demo samples' audio (33 samples, PTR 8-bit) | −45 | −180 |
| The demo songs, their 57 patterns, the sampler cartridges, settings, DJ's setup: 85 KB of records, in 4 KB records that never cross a block | −22 | −88 |
| **Left for the user** | **~20** | **~80** |

- **~80 KB is about 110 patterns** of 8 tracks and 64 rows (~680 B each at the demo songs' density,
  83 B a used track per 64 rows, measured), or ~65 of the demo songs' 128 rows. With four DX7, a
  Juno-106 and a TB-303 cartridge of the user's own (21 KB): about 100.
- **Deleting demo data gives it back:** the demo songs ~82 KB, the demo samples 180 KB. Moving the demo
  samples into ROM gives back the same 180 KB, and keeps them.

## 4. Settings, LOOPS and DJ's setup

- **No record, the firmware's defaults:** a new device runs on them (LOOPS empty), and nothing is copied
  at power-on. The record is written at the first SAVE that changes it, into the user area, as every
  save is.

## 5. ROM

- **Everything in ROM is read-only.** Nothing there is edited, and no save writes ROM; the device writes
  it only to add a thing and to delete one.
- **Adding is the user's choice, confirmed:** MOVE TO ROM in the SEL menu of a song, a pattern, a
  cartridge, and a sample in its cartridge's samples list. Only saved things move; nothing is created
  in ROM. The dialog says what it means: read-only from now on; a firmware update erases it unless
  backed up; a sample plays slower from ROM. Nothing goes into ROM by itself.
- **The samples list** (ENV on SAMPLE, [../ui/screens/instruments.md](../ui/screens/instruments.md)):
  its SEL menu, `SAMPLE 03`, becomes DELETE, MOVE TO ROM (MOVE TO USER AREA on a sample in ROM), FILL
  ROM; FILL ROM is left out when ROM has no room or no sample is left in the user area.
- **FILL ROM** moves as many samples as fit:
  - **from every sampler cartridge** in the user area, so it frees the most (rather than
    only the list's own cartridge);
  - **the set that fills ROM's free space best, not the biggest first:** with 100 KB free, two samples
    of 50 KB rather than one of 70 KB. It is a subset sum over the samples' sizes in 256-byte steps, a
    few milliseconds for a few hundred samples. Free space in several runs (after deletes) is filled
    run by run, the largest first, each with what is left;
  - **the dialog lists the result before anything moves:** how many samples, the KB they free, ROM's
    free space before and after, and MOVE TO ROM's warning; confirmed, they move as one step.
- **What can be done with a thing in ROM:**
  - use it: a song plays, its patterns play, cells play its instruments;
  - **MOVE TO USER AREA:** it comes back, editable again, when there is room;
  - **copy it out:** COPY and PASTE a slot or a pattern, CLONE a song or a cartridge to a free number in
    the user area;
  - **DELETE it,** which frees its ROM space (not the built-in instruments).
- **A move keeps the thing's number,** so no reference is rewritten. A sample's sampler cartridge may
  stay in the user area, editable (START, END, loops), while its audio sits in ROM.
- **Where it is shows:** a lock mark wherever a thing in ROM is listed (songs, patterns, cartridges,
  samples), and STATUS → STORAGE shows the two areas by name, USER and ROM
  ([../ui/screens/status.md](../ui/screens/status.md)).
- **Storage full:** a save that does not fit writes nothing and asks, as now
  ([../ui/saving.md](../ui/saving.md#storage-full)). When ROM has room, the dialog adds a line that says
  so, `MOVE THINGS TO ROM: 180 KB FREE` (the dialog is 37 characters wide): the user can move finished things (FILL ROM among them)
  and save again. No save goes into ROM.
- **ROM's blocks:** MOVE TO ROM packs the things moved into free blocks; a block is free again once
  everything in it is deleted or moved out.
- **Reading from ROM:** its free part cannot be read in place, only with direct reads (interrupts off,
  ~6 us + 0.7 us a byte). A sample there takes about twice the CPU of one in the user area, with bursts
  (measured on the FM-1, 16 voices). Patterns, songs and cartridges there are read the same way: a row's
  cells as the player reaches them, a slot at a note's start. Every reader takes records through one
  read function that reads in place from the user area and directly from ROM.

### Firmware updates

- **An install rewrites all of ROM:** what the user added is erased; the built-in instruments come with
  the new firmware, the same sounds.
- **Through the install page:** before installing, it reads the whole library back, both areas, and
  saves it as a disk (the backup, [../files/disk.md](../files/disk.md#versions)). After the install it
  offers to put the user's ROM things back where the new firmware leaves room; what does not fit stays in
  the backup, listed.
- **Through another installer, or the USB rescue:** no backup is taken. MOVE TO ROM's dialog says so:
  back up before updating.

## 6. What it gains

- **Installs never touch the user area.** Only what the user chose to put in ROM is at stake, and the
  install page backs it up.
- **Every built-in instrument plays at full speed,** and costs no space or RAM.
- **ROM's free part is not wasted:** up to ~225 KB more for finished work, by choice.
- **ROM has no saves:** no compaction and no wear there; only adds and deletes.

## 8. Still open

- **The dialogs' keys and words,** and the lock mark.
- **A disk with a cartridge at a built-in number:** the editor places it at a free number (rewriting its
  references), or refuses it.
- **Putting the user's ROM things back after an install:** written back after it (above), or carried in
  the install package itself (the update loader skips every sector that already holds what the package
  says, so they would survive an update that leaves room).
