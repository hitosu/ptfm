# Proposal: Juno-106 and Juno-60 banks on the EDITOR page, dropped or recorded

Status: **settled** (2026-11-11); its specs are written when the work on it starts, and lead from then on.

Juno-106 patches go around in four forms: `.syx` files of the Juno-106's own patch messages (it has no bank dump:
it sends one patch at a time), the libraries of the Juno-106 Librarian (`.106`), the text patch lists KR-106's
preset tools read (`.pat`), and recordings of the cassette interface, the way Roland and patch makers ship whole
banks. Juno-60 patches exist only as cassette recordings. **The EDITOR takes all of them as Juno-106 cartridges:**
the Juno-106's exactly, the Juno-60's converted to the Juno-106 patches that come closest. Today it reads DX7
`.syx` alone ([../editor.md](../editor.md#drops-and-conversions)). The cartridge record is unchanged: a Juno-106
patch dump converts both ways exactly already ([../files/instruments.md](../files/instruments.md#juno-106-and-tb-303)).

A **dump** below is what one save to tape writes: on a Juno-106 one bank group (A or B), 64 patches; on a Juno-60
its 56 patches. A Juno-60 numbers its patches by bank 1-7 and patch 1-8.

## 1. What is read

### 1.1 A Juno-106 patch

**The patch message (24 bytes):** `F0 41 30 0n pp`, 16 slider values, `sw1`, `sw2`, `F7`. `n` is the MIDI channel,
`pp` the patch number (0-127; the Juno-106 sends it, a receiving one ignores it). `F0 41 31 0n pp ...` has the same
layout: the panel's sound (MANUAL), not a stored patch. `F0 41 32 0n cc vv F7` changes one parameter and is not a
patch.

- **The 16 sliders, in this order, 0-127 each:** LFO RATE, LFO DELAY, DCO LFO, DCO PWM, DCO NOISE, VCF FREQ, VCF
  RES, VCF ENV, VCF LFO, VCF KYBD, VCA LEVEL, ENV A, D, S, R, DCO SUB. They are the cartridge's 16 sliders in the
  same order.
- **`sw1`:** bits 0-2 RANGE 16', 8', 4' (one set; none or several set read as 8'); bit 3 PULSE; bit 4 SAW; bit 5
  CHORUS off when 1; bit 6 CHORUS I when 1, II when 0 (only with bit 5 clear).
- **`sw2`:** bit 0 PWM SOURCE (0 LFO, 1 MAN); bit 1 ENV POLARITY (1 inverted); bit 2 VCA MODE (1 GATE); bits 3-4
  HPF inverted (`00` HPF 3, `01` 2, `10` 1, `11` 0). These are the meanings the firmware's Juno-106 engine reads;
  a published description that swaps bits 1 and 2 is wrong.

### 1.2 `.syx`

Any number of messages, read in file order. Each `30` and `31` message is a patch; the rest (`32`, other makers'
messages, bytes outside messages) is skipped and counted. A file of DX7 messages stays the DX7's; a file holding
both makes a cartridge of each.

### 1.3 `.106`, the Juno-106 Librarian's libraries

Big-endian throughout; a string is a u32 length and its UTF-8 bytes.

| Field | |
|---|---|
| magic | the 6 bytes `!j106\` |
| head | string `Library`, u32 3, u32 1, string the library's name, u32 0, u32 the patch count, u64 a time (ms), u32 0, u32 a check value |
| each patch | string its name; string a 36-character id; u64 a time; 20 × u16 the values; u32 a check value |
| end | u32 a check value |

- **The values are scrambled lightly:** value `i` (0-17: the 16 sliders as in 1.1, then `sw1`, `sw2`) of the
  library's patch `n` (from 0) is stored multiplied by `K[(i + 9n) mod 16]`, with K = 71 124 6 50 46 50 32 104 34
  68 40 103 61 43 49 45. Values 18 and 19 are 0. A stored value that does not divide, or divides to more than 127,
  makes the file unreadable (`NOT A JUNO-106 LIBRARY THIS PAGE READS`).
- **The check values are not read** (their rule is not known); nothing depends on them.
- **Names carry a slot label at times** (`A31 Clock Chimes`, `A-21 Kraftwerk Reso Bass`): a leading `A` or `B`, an
  optional `-`, two digits 1-8 and a space are dropped (section 2).

Checked: four libraries of 378 patches decode with every value exact; the factory library equals the factory
patches slot for slot.

### 1.4 `.pat`, the text patch lists

Text, a line a patch: 18 two-digit hex numbers (the 16 sliders, `sw1`, `sw2`, as in 1.1), a comma, the name.
**Read only when every non-empty line has that form:** `.pat` is also the extension of other instrument files, which
are refused as `NOT A FILE THIS PAGE READS` as now.

### 1.5 Juno-106 tape recordings

- **The signal:** a square wave whose level flips at every bit; **a 0 is a short level, about 0.16 ms, a 1 a long
  one, about 0.65 ms** (4:1). Tape and recording change both lengths, so they are told apart by their ratio, not by
  set times.
- **The framing:** a leader of 1s (about 0.4 s), then bytes of a start bit 0, 8 data bits (least significant
  first) and a stop bit 1, no gaps between.
- **A dump, 1,029 bytes:** `4A 55`; 64 patches of 16 bytes; a checksum (the sum of every byte before it, mod 256);
  `AA AA`.
- **A patch's 16 bytes:** the low 7 bits are the 16 sliders (1.1's order); **the top bits carry the switches:**
  `sw1`'s bits 0-6 are the top bits of bytes 0-6, `sw2`'s bits 0-4 those of bytes 8-12; byte 7's top bit is set in
  some patches and has no place in a patch (dropped); bytes 13-15's are 0.
- **A recording of both bank groups one after the other** holds two dumps.

Checked on recordings of the factory cassette: bank group B equals the factory patches slot for slot; group A in
62 of 64 (the recording holds other patches at A74 and A88; the libraries agree with each other).

### 1.6 Juno-60 tape recordings

- **The signal:** two tones, **a 1 is about 3.0 ms of about 2.35 kHz, a 0 the same time of about 1.3 kHz** (333 bits
  a second). Bytes of a start bit 0, 8 data bits (least significant first) and 2 stop bits 1, after a leader of 1s
  (about 2.6 s). A dump takes about 45 s.
- **A dump:** the byte `80`, then **64 records of 18 bytes:** the record's number (0-63), 16 bytes, a checksum (the
  18 bytes sum to 0, mod 256).
  - **Records 0-55 are the 56 patches' sliders,** 8 bits each, in this order: VCF ENV, VCF LFO, VCF KYBD, VCA
    LEVEL, ENV A, R, D, S, VCF FREQ, DCO NOISE, DCO SUB, VCF RES, DCO PWM, LFO RATE, DCO LFO, LFO DELAY.
  - **Records 56-62 are the 56 patches' switches,** 2 bytes a patch in patch order. Byte 0: bit 0 ENV POLARITY,
    bits 1-2 PWM SOURCE (0 LFO, 1 MAN, 2 ENV), bits 3-4 HPF, bit 5 VCA MODE, bit 7 LFO TRIGGER. Byte 1: bit 0 CHORUS
    I, bit 1 PULSE, bit 2 SAW, bit 3 SUB on, bit 4 CHORUS II, bit 5 CHORUS off.
  - **Record 63** is filler (`55`).
- **The values' meanings** in the Juno-60's own terms are KR-106's for its Juno-60 factory patches, read from the
  same tapes: LFO DELAY runs backwards (255 none, 18 the longest), ENV A starts at 28 (the fastest), VCA MODE 0 is
  GATE, VCA LEVEL 128 is unity, **the HPF's tape values 0, 1, 2, 3 are 122 Hz, FLAT, 269 Hz and 571 Hz** (the
  factory patch sheet's positions agree for 54 of bank A's 56). RANGE is not on the tape: the Juno-60 does not
  store it.
- **A recording of both dumps one after the other** holds two, each with its leader.

Checked on recordings of the factory cassette: every record read with its checksum right equals KR-106's Juno-60
factory data, sliders and switches. One patch (the second dump's 3-4) is damaged on the recording; KR-106's data
lacks its sliders too.

## 2. What the EDITOR makes of them

- **A file is one Juno-106 cartridge,** its patches in file order from slot `00`. One of more than 128 (a library,
  a `.syx` of many) fills a second cartridge, and so on. The status line says it as every drop's (`ADDED
  BASSES.SYX: 1 CARTRIDGE`), the converter's notes in brackets after it: `(1 PANEL COPY LEFT OUT)`.
- **A panel message (`31`) that is a copy of a patch in the same file** is left out and counted (a capture's first
  message usually is); one that is not is a patch in its place in the order.
- **Patch numbers in the messages are not used:** gaps close up.
- **Names:** a `.106` or `.pat` patch's name, its slot label dropped (1.3), converted as DX7 names are (capitals;
  any character outside the names' set a space; 10 characters). A patch with no name (`.syx`, tapes) or with a name
  that comes out empty is `PATCH` and its slot's number in hex: `PATCH00`-`PATCH7F`.
- **The cartridge's name:** a `.106`'s library name, else the file's name without its extension, converted as
  cartridge names are (12 characters); a file that makes several cartridges numbers them as the DX7 import does
  (`NAME 1`, `NAME 2`, the name cut to 9 characters first).
- **LEVEL 0** for every patch, as the DX7 import's.
- **Recognised by content,** as the DX7 `.syx` is: Juno-106 messages (`F0 41 30`, `F0 41 31`) whatever the
  extension; `.106` by its magic; `.pat` by its lines (1.4).

### Sounds that are tape recordings

- **Every sound dropped is tried as a tape recording** before it becomes a sample, on the audio the page decodes
  (any format, any rate, mixed to one channel): its first 20 seconds are searched for a tape's leader and first
  bytes, whatever its length; one found so is read to its end, every dump in it.
- **A sound that looks like a tape recording asks the question:** its leader and the dump's first bytes are found
  (a Juno-106's `4A 55`; a Juno-60's `80` and record `00`), whether or not the rest reads right. The dialog says
  which machine's tape it looks like and asks: `JUNO-106 TAPE? READ IT AS A CARTRIDGE` (`JUNO-60 TAPE? ...,
  CONVERTED TO JUNO-106`), `CARTRIDGE` or `SAMPLE`. With several sounds dropped at once, the dialog has `FOR ALL`
  beside it. Any other sound never sees it. The page has asked nothing during a drop until now: the question comes
  while the drop goes on, each file's in turn.
- **SAMPLE** makes a sample, as any sound.
- **CARTRIDGE on a dump that does not read** imports nothing of that file and says so in a dialog with `OK`, not in
  the status line: `JUNO106.WAV: NOT READ: THE TAPE'S CHECKSUM IS WRONG`. With several files dropped, one dialog
  lists every tape that did not read, once the others are in. A Juno-106 dump does not read when its checksum is
  wrong (its one checksum cannot say which patch is wrong, so none is taken) or it ends early; a Juno-60 dump when
  no patch reads whole.
- **A Juno-60 dump of which some patches read whole** is imported (its records have checksums of their own, and
  the factory cassette's own recording has a damaged patch): a patch whose records fail (its sliders' record, or the
  switches' record holding it) leaves its slot empty, and the status line names them in the Juno-60's numbering:
  `(3-4, 5-7 DAMAGED: LEFT EMPTY)`; in a recording of two dumps, `(DUMP 2: 3-4 DAMAGED: LEFT EMPTY)`.
- **Slots:** a Juno-60 dump is 56 slots in the Juno-60's order (slot `00` its patch 1-1, `37` its 7-8); a damaged
  patch's slot stays empty, so every other patch keeps its place. A recording of two Juno-60 dumps is one
  cartridge of 112 (the second from `38`); a Juno-106 recording of both bank groups one of 128.

### Takes from the recorder

A Juno's tape output recorded through the page's own recorder ([../editor.md](../editor.md#the-recorder)) is read
the same way, but **the recorder reads the take before it asks anything:**

- **While a take runs,** the whole incoming sound is read as a tape as it comes (no 20-second window: a leader may
  come at any time); once a leader and a dump's first bytes are found, a line under the waveform counts what has
  come in right. A Juno-60 dump sends its sliders' records first and its switches last, so the count is the
  sliders' records whose checksum is right, damaged ones said as they come: `JUNO-60 TAPE: READING… 23 OF 56, 1
  DAMAGED`. A Juno-106 dump has one checksum at its end, so the count is the patches whose 16 bytes came in with
  every byte's start and stop bits right, and the first byte that came in wrong says so: `JUNO-106 TAPE: READING…
  23 OF 64` / `JUNO-106 TAPE: BYTES COMING IN WRONG: CHECK THE LEVEL`. So a level too high or too low for the
  decoder shows within seconds; one too low to find a tape at all shows no line, and the meter shows why.
- **At STOP, a take that is a tape** says what it holds on that line, and **SAVE becomes `SAVE AS SAMPLE` and `SAVE
  AS CARTRIDGE`:** `JUNO-106 TAPE: 64 PATCHES, CHECKSUM RIGHT`; `JUNO-60 TAPE: 55 OF 56 PATCHES (3-4 DAMAGED),
  CONVERTED TO JUNO-106`; two dumps `JUNO-106 TAPE: 2 DUMPS, 128 PATCHES, CHECKSUMS RIGHT`. A take that is no tape
  keeps SAVE as today.
- **A tape that did not read** says why and how to go on, and `SAVE AS CARTRIDGE` is greyed: `JUNO-106 TAPE? THE
  CHECKSUM IS WRONG: RECORD IT AGAIN (TRY ANOTHER LEVEL)`; `JUNO-60 TAPE? NO PATCH READ WHOLE: RECORD IT AGAIN (TRY
  ANOTHER LEVEL)`. The dialog of a drop's tape that does not read is not needed here: the take is read before the
  keys are pressed.
- **A part of the take selected** is read on its own, whatever the whole take was found to be: the line says what
  the part holds, and the keys follow it (a part that is a tape, in a take that was not, brings `SAVE AS SAMPLE`
  and `SAVE AS CARTRIDGE`; so one dump is taken out of a longer take); `WHOLE TAKE` reads all of it again.
- **`SAVE AS CARTRIDGE`** puts a Juno-106 cartridge on the TABLE, its patches as in this section's rules (names
  `PATCH00` ..., LEVEL 0, damaged Juno-60 slots empty), its source `RECORDING` and the time, and closes the
  recorder; the status line names it. One step of FILES' UNDO. **Its name** follows the naming rule from `TAKE`,
  counted among the cartridges' names (the first `TAKE00`, `TAKE01` ... no cartridge has), within a cartridge
  name's 12 characters. **It keeps no audio:** the take's original is not written (so a browser that cannot keep
  more audio does not refuse it), and the take is gone once the recorder closes, as after any SAVE. `SAVE AS
  SAMPLE` is SAVE as today.
- **Closing with a tape take not saved** asks as now, its SAVE the two keys: `SAVE AS SAMPLE`, `SAVE AS CARTRIDGE`
  (greyed as above), DISCARD or STAY.

## 3. Juno-60 patches as Juno-106 ones

The two share one voice design, but the same slider is a different sound on each: the Juno-60's envelope is
analog, the Juno-106's computed; their VCF, LFO and modulation scales differ. **The conversion keeps the sound,
not the slider:** each Juno-60 value is taken to its quantity (below) by KR-106's Juno-60 model, and the Juno-106
value is the one whose quantity on **PT/FM's engine** (its own tables, indexed by the patch's byte as on the FM-1)
comes closest.

- **The reference is KR-106's Juno-60 model, as it stands.** It is the only one at hand, and for most sliders it
  is its Juno-6 model (the same envelope chip and circuits; its notes say the Juno-60's pots differ): ENV A, D, R,
  LFO RATE, LFO DELAY, DCO LFO, VCF LFO, DCO SUB, RES and the VCA's curve. VCF FREQ, NOISE, the HPF and the KYBD's
  reference note are its Juno-60's own. The conversion is as close to a Juno-60 as that model is.
- **KR-106's sound code leads:** what its Juno-60 mode plays (its parameter setting and its voice, envelope and LFO
  code), not its value-display functions, which differ from what it plays for VCF ENV, LFO DELAY and ENV D and R.
  The display functions its parameter setting itself calls are its sound: DCO LFO's, VCF LFO's, DCO SUB's and
  NOISE's levels, the envelope's time constants, LFO RATE's and VCF FREQ's.
- **Computed, not rendered, each quantity defined the same on both sides:**

  | Slider | Quantity compared | Kind |
  |---|---|---|
  | ENV A | the times to half the peak and to the peak (the Juno-60's attack charges toward a level above its peak, the Juno-106's is a straight ramp), the Juno-106 value closest in both on a logarithmic scale | table |
  | ENV D | the time to go 90 % of the way from the peak to the sustain level | table |
  | ENV R | the time from the sustain level to a tenth of it (the Juno-60's release heads below zero, so it is quicker than its decay at the same slider: D and R are two tables) | table |
  | ENV S | with VCA MODE ENV, the sustain's loudness through each VCA's own curve (the two differ most at low levels); with GATE, the envelope's level (it moves the filter alone) | per patch |
  | VCF FREQ | the cutoff in Hz, on a logarithmic scale | table |
  | VCF ENV, VCF LFO, VCF KYBD | the cutoff's movement in octaves at the patch's own cutoff (VCF ENV at the envelope's peak, at its polarity's scale: the Juno-60's differs between + and −); on the Juno-106 the sum of the cutoff and its movements is held in range and bends above about 10 kHz, so the amount depends on the cutoff | per patch |
  | RES | the filter's feedback; the Juno-60's top reaches past the Juno-106's, which the Juno-106's 127 then stands for | table |
  | LFO RATE | Hz | table |
  | LFO DELAY | the time to half depth (the Juno-60's a smooth fade-in, the Juno-106's a hold, then a ramp in steps) | table |
  | DCO LFO | semitones | table |
  | DCO PWM | the pulse's width (the Juno-106's is full at 105) | table |
  | DCO SUB, DCO NOISE | the level against the saw's in each machine's mix (the loudness is LEVEL's, below) | table |
  | VCA LEVEL | decibels (one scale on both) | table |

  The tables and the per-patch rules are made by one generator, kept in the tree with what it makes; it reads
  KR-106's sources from a path given to it, and KR-106 (GPL-3.0) is credited in the header of the file it writes,
  as for the engine's own tables.
- **The HPF:** the Juno-60's positions are FLAT, 122 Hz, 269 Hz and 571 Hz (its tape values in 1.6), the
  Juno-106's BASS BOOST, FLAT, 236 Hz and 754 Hz. FLAT goes to FLAT, 269 Hz to 236 Hz, 571 Hz to 754 Hz, and 122 Hz
  to whichever of FLAT and 236 Hz the check finds closer. BASS BOOST is never chosen.
- **The tape's meanings are checked against the source they come from, not by the check below** (both sides of
  it read them the same way, so it could not see one wrong): the HPF's values, VCA MODE's 0 as GATE, LFO DELAY
  backwards and ENV A from 28, against KR-106's reading of its factory tapes and the factory patch sheet.
- **What has no Juno-106 counterpart:**
  - **PWM SOURCE ENV:** replaced by a rule on the patch's own values, which the page computes for any tape: MAN
    or LFO, and the PWM amount, picked from the envelope's settings. It matters only with PULSE on and DCO PWM
    above 0 (13 of the 20 factory patches that use it); the rule is worked out on the PC with those and checked by
    the check below, and the status line counts only those: `(9 WITH PWM BY ENV: THE CLOSEST KEPT)`.
  - **RANGE:** 8'.
  - **LFO TRIGGER** (the Juno-60's manual LFO): dropped; the LFO runs as with AUTO.
  - **SUB off:** DCO SUB 0, whatever its slider.
  - **CHORUS I and II both set:** II. Neither: off.
- **Loudness:** every converted patch has LEVEL 0, as every import's; the level the Juno-60 differs by (its mix of
  oscillators, its VCA) is not made up for, since LEVEL and AUTO LEVEL are there for that.
- **The check, run on the PC before the work is done,** its figures in the version's report. Each Juno-60
  factory patch, at RANGE 8' on both sides, is played through KR-106 in its Juno-60 mode and its conversion
  through PT/FM's engine, at three notes (C2, C4, C6), a held note of 2 s and its release. Compared over time, each
  measure on its own: the level's shape (attack, decay, sustain, release), the brightness (the spectrum's
  centroid: the filter, its envelope and LFO), pitch and vibrato. **The yardstick is measured in the same run:** the
  Juno-106 factory patches through KR-106 in its Juno-106 mode and through PT/FM's engine, the same notes and
  measures; a converted patch passes a measure when it is within that measure's spread there (the 95th percentile
  of the Juno-106 patches' figures, so one odd patch does not set the bar). KR-106 is given each byte as PT/FM's
  engine reads it (DCO LFO through KR-106's own undoing of its slider taper, DCO PWM against 105), and its
  per-voice variations and drift are off in both modes. The overall level is reported, not counted. Patches past the yardstick are listed with why (the PWM by ENV ones above all). A table or
  rule the check finds off is corrected in the generator and the check run again. The harness is kept in the tree
  with the generator and reads KR-106's sources and its factory data from the same path.

## 4. Tests

The public repository holds no factory patches, no libraries and no recordings found elsewhere: **the tests make
their own.** From patches of their own (every field at its ends and between):

- `.syx` (with `31` copies, `32` messages, gaps, other bytes, a DX7 dump in the same file), `.106` (written with the
  scrambling, a library of more than 128), `.pat` (and a `.pat` of another kind, refused), and tape recordings of
  both machines synthesised by the tests at several rates, levels and amounts of noise, one a damaged copy, each read
  back exactly;
- the names (slot labels, long names, empty names), the cartridges' names and the notes in the status line;
- the Juno-60 conversion against the generator's tables and rules, field by field;
- in the headless Chrome: a tape recording dropped, the question answered both ways and with `FOR ALL`, a tape
  that does not read and its dialog, a sound that is no recording never asked; the recorder with a fake input
  playing synthesised tapes: the count while it runs, the line at STOP, `SAVE AS CARTRIDGE` (whole and a selected
  part), greyed for a tape that does not read, closing with a tape take not saved.

The checks against the real files (the factory cassette's recordings, the factory library, a `.syx` capture) and
section 3's check are run on the PC and reported in the version's report.

## 5. Also changed

**The firmware does not change:** the cartridge record, the Juno-106 engine and the EDITOR's WebAssembly stay as
they are; this work is the EDITOR page's alone. Section 3's check builds the engine on the PC as it is.

- **The specs:** [../editor.md](../editor.md#drops-and-conversions) (Drops and conversions takes sections 1 and 2
  in brief, the conversion of section 3, the dialogs; its Tests section the tests above);
  [../README.md](../README.md) lists this proposal; any other spec naming what the EDITOR reads says it too.
- **The manual, its HTML page and its PDF:** the EDITOR chapter's list of what a drop reads takes Juno-106 banks
  (`.syx`, `.106`, `.pat`), tape recordings of both machines and what the Juno-60's conversion keeps and loses;
  both are built again (`dist/manual/manual.html`, `dist/manual/ptfm-manual.pdf`) and pass the manual's tests.
- **The page's texts:** + ADD FILES' title and the TABLE's empty text name the new kinds (`JUNO-106 .SYX, .106,
  .PAT`, `JUNO TAPES`); the file picker offers `.106` and `.pat` too.
- **`CHANGELOG.md`, Next version:** a FEATURE entry; **the next version's report:** a section for this work.

## 6. Not in this work

- **Writing a Juno-106 cartridge out** as `.syx` or as a tape recording (DX7 cartridges have no export either).
- **KR-106's own patch banks** (a binary format of its own).
- **Alpha Juno** (Juno-1, Juno-2, MKS-50) files: another instrument, another format.
- **Juno-6** (no memory) and **MKS-7**.
- **The Juno-60's DCB** messages.
